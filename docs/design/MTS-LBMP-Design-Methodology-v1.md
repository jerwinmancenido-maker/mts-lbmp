# MTS LBMP Design Methodology v1

## Design Rule

```text
Premium look, simple operation.
```

The platform should look modern and professional, but operations screens must be simple enough for fast daily use by non-technical staff.

## Design Priorities

- Button-heavy workflows
- Large tablet targets
- Minimal typing
- Scan-first actions
- Clear status colors
- Friendly messages
- English/Tagalog switchable
- Dark mode configurable
- Fast receiving
- Fast loading
- Fast delivery

## Operations UI Pattern

Each operations screen should answer:

```text
What is the current task?
What should the user tap next?
What problem blocks completion?
What document or QR must be printed?
```

## Receiving UX Rule

Receiving should use one simple field:

```text
Product / Package Description
```

Barcode scanning may auto-fill that description. If barcode is unknown, staff can quick-add the description and continue.

Customer DR OCR may suggest sender, consignee, DR number, and descriptions, but staff must review before saving.

## Error Message Style

Messages should be friendly and direct.

Examples:

```text
This package has no price yet. Add a price before loading.
This package is for Naga. You are loading a Daet trip.
Please upload a photo because the package condition is Damaged.
Delivery cannot be completed yet. Signature and photo are required.
```

## Visual Direction

- Owner/admin: premium SaaS
- Staff tablet screens: simple POS/tablet workflow
- Customer portal: friendly and easy to understand
- Public website: corporate logistics credibility
